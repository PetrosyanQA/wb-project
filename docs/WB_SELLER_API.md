# Ի՞նչ ավելացնել WB Seller API-ով — առաջնահերթությունների քարտեզ

MPStats-ը ասում է՝ **ինչ է կատարվում շուկայում**։ WB Seller API-ն ասում է՝ **ինչ է կատարվում քեզ հետ
և ինչ արժե դա իրականում**։ Երկուսը միասին վերացնում են մոդելի 3 ամենավտանգավոր ենթադրությունը.

| Ենթադրություն մինչ այժմ | Ինչով ենք փոխարինում | Կարգավիճակ |
|---|---|---|
| կոմիսիա 22% (գուշակած) | `/api/v1/tariffs/commission` — ճշգրիտ % ըստ предмет-ի | ✅ արված |
| լոգիստիկա/պահեստ՝ միջին տարիֆներ | `/api/v1/tariffs/box` — ըստ կոնկրետ պահեստի + коэф | ✅ արված |
| выкуп 75% (գուշակած) | `/api/v1/supplier/orders` + `/sales` — ֆակտ | ✅ արված |
| ДРР 12% (գուշակած) | `/adv/v2/fullstats` — ֆակտիկ CPC/CPM/ДРР | 🟡 client-ը կա, հաշվետվությունը՝ ոչ |

## Tier 1 — հիմա, մինչև առաջին գնումը (ամենաբարձր ազդեցությունը)

### 1. Тарифы → իրական յունիտ-էկոնոմիկա ✅
```bash
python -m src.wb_seller box --warehouse "Коледино"
python -m src.wb_seller commission --subject "Ножи кухонные"
python -m src.sync_tariffs --warehouse "Коледино" --subject "Ножи кухонные" --apply
```
Գրում է `config/tariffs_auto.yaml`, որը ավտոմատ merge է լինում `unit_economics.yaml`-ի վրա։
**Ազդեցությունը.** կոմիսիայի 22%→18.5% տարբերությունը մեր թեստում շահույթը փոխեց 376→443 ₽
(+18%)։ Սխալ տարիֆով հաշված ապրանքը կարող է թվալ շահավետ, երբ իրականում զրոյական է։

### 2. Приёмка-ի գործակիցներ → որ պահեստ և ո՞ր օրը տանել ✅
```bash
python -m src.wb_seller acceptance --free-only
```
Կոեֆիցիենտ ×3–×5-ը սկսնակի խմբաքանակի վրա կարող է ուտել ամբողջ առաջին շահույթը։
Անվճար պատուհան գտնելը $2,000 բյուջեի դեպքում իրական փող է։

### 3. Контент → предмет + պարտադիր բնութագրեր ✅
```bash
python -m src.wb_seller subjects "нож"
```
`subjectID`-ն պետք է կոմիսիայի ճշգրիտ կապի համար, իսկ `content/v2/object/charcs/{id}`-ը տալիս է
այն բոլոր բնութագրերը, որոնք պետք է լրացնել քարտում — **դա SEO-ի և ինդեքսավորման հիմքն է**,
և ցույց է տալիս, թե ապրանքը որքան «փաստաթղթային» է (սերտիֆիկատ, բաղադրություն, տարիք)։

## Tier 2 — մեկնարկից հետո (2–4 շաբաթ)

### 4. Статистика → իրական выкуп % ✅
```bash
python -m src.wb_facts buyout --days 30
```
Սա **ամենակարևոր թիվն է** քո մոդելում։ 75% vs 60% выкуп-ը 1,490 ₽ ապրանքի վրա
մարժան իջեցնում է ~5 կետով։ Հաշվարկը՝ `sales / (orders − cancels)` ըստ SKU-ի,
ելքում պատրաստի արժեք՝ `operations.buyout_pct`-ի համար։

### 5. Аналитика → վաճառքի ձագար (ախտորոշում) ✅
```bash
python -m src.wb_facts funnel --days 30 --nm 123456789
```
Ցույց է տալիս՝ խնդիրը **նկարն է, գինը, թե ապրանքը**.
- քիչ բացումներ → SEO/գովազդ
- ցածր CR→զամբյուղ → գլխավոր նկար + գին
- ցածր CR→պատվեր → գին/առաքման ժամկետ
- ցածր выкуп → ակնկալիք ≠ իրականություն

### 6. Ռեգիոններ → պահեստի ռազմավարություն ✅
```bash
python -m src.wb_facts regions --days 30
```
Индекс локализации-ն ուղղակիորեն մտնում է լոգիստիկայի գնի մեջ։

### 7. Продвижение → իրական ДРР 🟡 (client-ը պատրաստ է՝ `advert_stats`)
`/adv/v1/promotion/count` + `/adv/v2/fullstats` → փաստացի CPC, CPM, ЦРР ըստ արշավի։
**Ինչ կավելացնենք.** ավտոմատ համեմատություն «պլանային ДРР 12%» vs ֆակտ, և զգուշացում,
երբ գովազդի ինքնարժեքը գերազանցում է մարժան (այսինքն՝ վաճառում ես վնասով)։

### 8. Финансовый отчёт (`reportDetailByPeriod`) 🟡 (client-ը պատրաստ է)
srid-մակարդակի դետալիզացիա՝ բոլոր պահումները, տուգանքները, приёмка, պահեստավորում։
**Ինչ կավելացնենք.** «պլան vs ֆակտ» հաշվետվություն՝ `unit_econ`-ի կանխատեսած շահույթը
ընդդեմ WB-ի փաստացի վճարման։ Սա միակ ձևն է իմանալու՝ որտեղ է կաթում փողը։

2. Ստեղծիր **«Только на чтение»** թոքեն։ Առանց գրելու իրավունքի AI-ը ֆիզիկապես չի կարող
   փոխել գները, ջնջել քարտերը կամ գովազդ գործարկել։
3. Կատեգորիաներից ընտրիր միայն պետքականները՝ **Тарифы, Контент, Статистика, Аналитика**

4. Թոքենի ժամկետը **180 օր** է — օրացույցում դիր հիշեցում։
5. «Тестовый контур» վանդակը **մի՛ նշիր** (այլապես իրական տվյալ չի գա)։
6. `.env`-ը արդեն `.gitignore`-ում է։ Երբեք մի commit արա այն։

- 📌 այն **պահեստի անունը**, որտեղ պլանավորում ես պահել (օր. Коледино, Электросталь, Тула)
- 📌 **предмет**-ի անունը, երբ նիշան ընտրված լինի (կոմիսիայի ճշգրիտ %-ի համար)
- 📌 արդեն վաճառք ունե՞ս WB-ում (եթե այո՝ միանգամից գործարկում ենք `wb_facts buyout`)

## Как создать токен «только на чтение» и какие категории отметить

**Путь:** WB Partners → нажать на имя профиля → **Настройки** → **Доступ к API** →
**Создать новый токен**

1. **Имя токена:** `mpstats-research` (чтобы потом не удалить случайно)
2. ☑️ **«Только на чтение»** — обязательно поставить. По такому токену нельзя изменить
   цены, остатки, карточки или рекламу. Даже при утечке ущерб ограничен чтением.
3. ❌ **«Тестовый контур»** — НЕ ставить. Это песочница с выдуманными данными.
4. Отметить категории (список ниже) → **Создать токен**
5. **Скопировать сразу** — токен показывается ОДИН раз. Срок жизни — 180 дней.

### Какие категории нужны именно этому проекту

| Категория | Нужность | Что даёт | Какой скрипт |
|---|---|---|---|
| **Тарифы** | 🔴 обязательно | логистика, хранение, приёмка, комиссия по предмету | `sync_tariffs`, `unit_econ` |
| **Контент** | 🔴 обязательно | ID предметов, характеристики для карточки | `wb_seller subjects` |
| **Статистика** | 🟡 если уже продаёшь | твои заказы и продажи → реальный **процент выкупа** | `wb_facts buyout` |
| **Аналитика** | 🟡 если уже продаёшь | воронка: показы → корзина → заказ → выкуп | `wb_facts funnel` |
| **Поставки** | 🟢 полезно | коэффициенты приёмки по складам | `wb_seller acceptance` |
| **Продвижение** | ⚪️ не нужно | статистика рекламных кампаний | `wb_seller advert` |
| Маркетплейс, Цены и скидки, Документы, Вопросы и отзывы | ⚪️ не нужно | — | — |

**Минимум для выбора товара с нуля:** Тарифы + Контент.
**Полный набор:** + Статистика + Аналитика + Поставки.

### Проверить права токена БЕЗ запроса

```bash
python -m src.wb_seller decode
```

Читает JWT локально (просто base64, ничего никуда не отправляется) и показывает:
какие категории включены, стоит ли «Только на чтение», не sandbox ли это и сколько
дней осталось до истечения. Удобно, когда не помнишь, что отмечал при создании.

### Проверка после вставки в `.env`

```bash
mps.bat src.wb_seller check          # Windows
python -m src.wb_seller check        # macOS/Linux
```

Выводит таблицу: какая категория доступна ✅, какой не хватает ❌ — и что именно
перестанет работать без неё.

### Важные нюансы

- **401 / 403** = этой категории нет в токене или токен просрочен (180 дней) → создать новый.
- **429** = превышен лимит запросов. У тарифов `commission` лимит **1 запрос в минуту**,
  у `box` — 60/мин, у `orders`/`sales` — **1 запрос в 61 секунду**. В коде стоит троттлинг.
- Режим «только на чтение» блокирует методы, которые **создают** что-либо. Отчёт
  «Платное хранение» создаётся POST-задачей, поэтому в read-only он недоступен — но этому
  проекту он не нужен, хранение считается из тарифов.
- Токен привязан к кабинету (юрлицу). Если кабинетов несколько — нужен отдельный токен на каждый.
- Если токена WB вообще нет — проект работает, просто тарифы берутся из
  `config/unit_economics.yaml` (значения по умолчанию, менее точные).

## Воронка продаж v3 (v2-ը անջատված է)

`POST analytics-api /api/analytics/v3/sales-funnel/products`
```json
{"selectedPeriod": {"start": "2026-09-01", "end": "2026-09-30"},
 "pastPeriod":     {"start": "2025-09-01", "end": "2025-09-30"},
 "nmIds": [], "brandNames": []}
```
Պատասխանը՝ `{"data": {"products": [...], "currency": "RUB|AMD"}}`,
ամեն product-ում՝ `statistic.selected.{orderCount, orderSum, buyoutSum, buyoutAmount}`։

- ❌ `/api/v2/nm-report/detail` **անջատված է 09.12.2025**-ից → 404 ընդմիշտ
- ⚠️ Վերադարձնում է **միայն քո սեփական** ապրանքները → նիշա-հետազոտության համար պետք է MPStats
- ⚠️ Տվյալները ուշանում են 20-30 րոպե; `orderSum` կարող է 0 լինել `orderCount>0`-ի դեպքում

## Բազմա-թոքեն

`.env`՝ `WB_SELLER_TOKEN` և/կամ `WB_TOKEN_*`։ Երթուղղումը՝ ըստ JWT bitmask-ի, least-privilege։
`python3 -m src.wb_seller decode` → բոլոր թոքենները + երթուղղման քարտեզ (0 հարցում)։
