## 1. Ինչու՞ պարզապես MPStats-ի ինտերֆեյսը բավական չէ

| Թակարդ | Ինչ է երևում MPStats-ում | Ինչ է իրականում |

| Լավ մարժա | «Գինը 1,500 ₽, ինքնարժեքը 400 ₽» | Կոմիսիա + լոգիստիկա + невыкуп + ДРР + հարկ = 1,150 ₽ |

## 2. Արագ սկիզբ (5 րոպե)

```bash
cd mpstats-research
cp .env.example .env          # ներսում դիր MPSTATS_TOKEN-ը (mpstats.io/userpanel → API token)
pip install -r requirements.txt

python -m src.niche_scan --demo          # ստուգում առանց API-ի
python -m src.doctor --path "Дом/Кухня"  # ⚠️ ՊԱՐՏԱԴԻՐ առաջին քայլ՝ կապ + դաշտերի ստուգում
```

## 3. Ճիշտ խողովակաշարը՝ 7 փուլ

### Փուլ 0 — Չունե՞ս նիշա։ Սկսիր այստեղից 🆕
```bash
python -m src.discover --depth 2 --top 20        # ամբողջ WB-ն, ~30 հարցում
python -m src.discover --depth 2 --deep 5        # + խորը սքան տոպ-5-ի վրա
```
Երկու փուլ.
1. **Էժան մաղ** — հարյուրավոր ենթակատեգորիաներ միայն ագրեգատներով (շրջանառություն, SKU, միջին գին)
2. **Զոնդ** (ավտոմատ տոպ-10-ի վրա) — քաշում է ընդամենը ՏՈՊ-20 քարտը ամեն նիշայից → երևում են
   **մոնոպոլիան, աճը, կարծիքների բարիերը և թարմ քարտերի հաջողությունը**

Վերջնական սքոր = 40% էժան + 60% զոնդ։ Հենց այստեղ է, որ «գեղեցիկ» նիշան կարող է ընկնել՝
օր. `Дом/Кухня/Органайзеры` 95 → 53, քանի որ տոպ-10-ը վերցնում է 83%-ը։
Claude Code-ում՝ `/find-niche`։

### Փուլ 0.5 — Ճշգրիտ path
MPStats API-ն path-ը համեմատում է **բառացի**։ Սխալ path = դատարկ պատասխան + այրված լիմիտ։
```bash
python -m src.mpstats_client categories "чехл"
```
> API: `POST category/list` · Վեբ: «Категории»

### Փուլ 1 — Նիշաների քարտեզ
Վերցնում ենք ծնող կատեգորիան և բացում ենթակատեգորիաները/предмет-ները։
```bash
python -m src.niche_scan --path "Дом/Кухня" --children categories --top 12 --dry-run
```
> API: `POST category/categories`, `POST category/subjects`

### Փուլ 2 — Զանգվածային սքրինինգ (այստեղ է որոշվում 80%-ը)
Ամեն նիշայի համար քաշվում է մինչև 500 քարտ և հաշվվում 8 ցուցանիշ՝ մեկ սքորի մեջ։
```bash
python -m src.niche_scan --path "Дом/Кухня" --children categories --top 12
```
Ստանում ես `reports/niche_scan_<ամսաթիվ>.md` — ռեյտինգ + ամեն նիշայի քարտ + կարմիր դրոշներ։
> API: `POST category/items`, `POST category/by_date`

### Փուլ 3 — Երկարաժամկետ դինամիկա (12–18 ամիս) 🆕
```bash
python -m src.trend_scan --path "Автотовары/Органайзеры" --days 540 --snapshots 4
```
Քաշում է **540 օրվա օրական շարքը** (2 հարցում) + **4 կտրվածք** կառուցվածքի համար (4 հարցում) →
տրենդ %/ամիս, YoY, սեզոնային ինդեքս 12 ամսվա, տատանողականություն, **հագեցման ստուգում**
(₽ մեկ քարտի վրա ժամանակի մեջ) և **մուտքի պատուհան** (ե՞րբ պատվիրել)։
Ամեն գործարկում պահվում է `data/history.db`-ում։

### Փուլ 3.5 — Խորացում տոպ-3 նիշայի մեջ
Ձեռքով/Claude-ով նայում ես.
- **գնային սեգմենտացիա** — որ միջանցքն է վերցնում ծավալը (`POST category/price_segmentation`)
- **սեզոնայնություն** — հիմա մտնելը ուշ չէ՞ (`GET category/season_effects/annual`, `category/forecast/trend`)
- **երկու ժամանակահատվածի համեմատություն** — նիշան աճո՞ւմ է (`POST category/compare`)

### Փուլ 4 — Մրցակիցների աուդիտ
```bash
python -m src.sku_audit --sku 12345678 --days 30
```
Տալիս է քարտի դինամիկա, պաշարներ, տոպ բանալի բառեր (SEO-ի հիմք), նմանատիպ ապրանքների աղյուսակ։
**Ամենաարժեքավորը՝ կարծիքները** (`items/<id>/comments`) — այնտեղից է գալիս «ի՞նչով ենք լավը լինելու»։
> API: `GET items/{sku}`, `items/{sku}/sales/stores`, `items/{sku}/keywords`, `items/{sku}/comments`, `POST similar/items`

### Փուլ 5 — Յունիտ-էկոնոմիկա նիշայի **մեդիան** գնով
```bash
python -m src.unit_econ --price 1490 --cost 380 --volume 0.5 --buyout 82 --drr 15
```

Հաշվում է WB կոմիսիա, լոգիստիկա невыкуп-ի հետ, պահեստավորում, приёмка, գովազդ, հարկ,
break-even գին, ROI և **քանի միավոր է հերիքում $2,000-ը**։

### Փուլ 6 — Ոչ-տվյալային ռիսկեր (այստեղ են մահանում լավ թվերը)
Սերտիֆիկացիա/ՀՀ→ՌԴ մատակարարում, «Честный знак» մարկիրովկա, փխրունություն, ծավալային քաշ,
մատակարարի lead time, բրենդ/պատենտ։ Չկա API, որը սա կասի — սա չեկ-լիստ է՝ `docs/CHECKLIST.md`։

## 4.5 WB Seller API — երկրորդ տվյալների աղբյուրը 🆕

MPStats-ը ասում է՝ **ինչ է անում շուկան**։ WB Seller API-ն ասում է՝ **ինչ արժե դա քեզ իրականում**։

| Ենթադրություն (գուշակած) | Ֆակտ (WB API) | Հրաման |
|---|---|---|
| կոմիսիա 22% | ճշգրիտ % ըստ предмет-ի | `wb_seller commission --subject "…"` |
| լոգիստիկա միջին տարիֆով | ըստ կոնկրետ պահեստի + коэф | `wb_seller box --warehouse "…"` |
| выкуп 75% | `sales / (orders − cancels)` | `wb_facts buyout --days 30` |
| приёмка «հավանաբար անվճար» | ազատ պատուհաններ coef=0 | `wb_seller acceptance --free-only` |
| ДРР 12% | փաստացի CPC/CPM | `advert_stats()` (client-ը պատրաստ է) |

```bash
python -m src.wb_seller check      # ստուգում՝ թոքենն ինչ է բացում
python -m src.sync_tariffs --warehouse "Коледино" --subject "Ножи кухонные" --apply
```

`sync_tariffs`-ը գրում է `config/tariffs_auto.yaml`, որը ավտոմատ merge է լինում
`unit_economics.yaml`-ի վրա → **յունիտ-էկոնոմիկան դառնում է փաստացի, ոչ թե մոտավոր**։
Թեստում կոմիսիայի 22%→18.5% ճշտումը շահույթը փոխեց 376 → 443 ₽ (+18%)։

🔒 **Անվտանգություն.** ստեղծիր **«Только на чтение»** թոքեն միայն Тарифы/Контент/Статистика/
Аналитика կատեգորիաներով, դիր `.env`-ում, **ոչ մի դեպքում մի ուղարկիր չաթում**։
Մանրամասն՝ `docs/WB_SELLER_API.md`։

## 6. API լիմիտի հիգիենա

- 500 տող = **1 հարցում**։ 12 նիշա × (items + by_date) ≈ 25–30 հարցում։
- Քեշը միացված է (24 ժամ)։ Նույն սքանը կրկնելը լիմիտ **չի** ծախսում։
- Միշտ սկսիր `--dry-run`-ով. տեսնում ես նիշաների ցանկը և հարցումների գնահատականը։
- `python -m src.mpstats_client limit` — մնացորդը։ 429-ի դեպքում կլիենտը ինքը սպասում է
  `Retry-After`-ի չափ և կրկնում։

## 7. Ազնիվ սահմանափակումներ

1. MPStats-ի վաճառքի տվյալը **գնահատական է** (±10–20%, հատկապես FBS-ում)։ Որոշումը մի՛ կառուցիր
   մեկ թվի վրա — նայիր 2-3 անկախ անկյուն։
2. `revenue`-ն արտացոլում է պատվերները, ոչ թե փաստացի գնված ապրանքը — **выкуп %-ը** քո
   էկոնոմիկայի ամենակարևոր փոփոխականն է, և այն API-ում ճշգրիտ չկա։ Վերցրու պահպանողական։
3. WB տարիֆները փոխվում են. `config/unit_economics.yaml`-ը թարմացրու ամիսը մեկ։
4. AI-ը (այդ թվում՝ ես) կարող է սխալ մեկնաբանել դաշտը։ Ցանկացած «շոկային» թիվ ստուգիր
   վեբ-ինտերֆեյսում, նախքան փող ծախսելը։
