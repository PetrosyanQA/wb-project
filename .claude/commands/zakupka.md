# Закупка (поставщик → образцы → партия)

Запрос пользователя: **$ARGUMENTS** (по умолчанию — товар из `PROJECT_STATE.md`).

## Что делает (простыми словами)
Доводит выбранный товар до оплаты партии без сюрпризов: готовит запрос поставщику, проверяет его ответ, считает точную
себестоимость «под ключ», планирует образцы и тест качества, проверяет документы и решает, **сколько штук брать**.
Партию оплачиваем только когда пройдены **3 условия**: цена «под ключ», тест образцов, реальная СПП на нашей карточке.

## Как запустить
- `/zakupka` — для текущего товара.
- `/zakupka пришло КП, файл docs/suppliers/...` — разобрать ответ поставщика.

## Шаги
| # | Шаг | Чем | Стоимость |
|---|---|---|---|
| 0 | **Найти фабрики по описанию (без фото)**: ТЗ → китайские запросы → все офферы 1688 → баллы за совпадение с ТЗ (+ молния, материал, комплект, размер; − магнит, ткань, принт, детское, дороже потолка) → карточки топа: цены по вариантам, цвета, вес, MOQ. 3–5 кандидатов + 1 «эталон качества» (точно по ТЗ, даже если дороже) | `python -m src.spec_find search --spec <ключ>` → `rank` → `detail --top 8` (ТЗ — ключ в `SPECS` в `src/spec_find.py`); по фото — `/poisk-po-foto` | 1 кредит Bright Data на запрос/карточку |
| 0a | **Потолок цены фабрики (¥)**: экономика при нашей цене продажи для ¥ 14 / 17 / 20 / 22 / 28 — себестоимость «под ключ», прибыль старт/обычно, риск убытка (Монте-Карло), деньги на партию. Потолок = наибольший ¥ с риском ≤ 5 % | `src/screen_white.econ`, `python -m src.monte_carlo …` | 0 |
| 1 | **Запрос КП** (текст на русском/английском/китайском): цена за штуку на 2–3 объёма партии, **код ТН ВЭД**, ставка НДС и пошлины, вес и размер короба, срок, условия «под ключ» до склада | черновик в чат + в `docs/suppliers/<товар>_rfq_<дата>.md` (ссылки на 3–5 офферов 1688 из шага 0, ТЗ по-русски и по-китайски, 3 объёма, доработки и их доплата, образцы) → **отправляет только пользователь** | 0 |
| 2 | **Разбор КП**: все платежи (товар, агент, банк, доставка, таможня, пошлина, НДС, страховка, фикс) → цена «под ключ» за единицу; несоответствия (материал ≠ код ТН ВЭД, НДС ≠ 22 %) — вопросами поставщику | `docs/suppliers/`, пример разбора `yuanexim_offer_2026-10-22.md` | 0 |
| 3 | **Пересчёт экономики** по КП (не по целевой цене) + стресс-тест: риск убытка ≤ 15 % (лучше ≤ 5 %) | `src/unit_econ.py`, `python -m src.monte_carlo …`, `python -m src.budget_sim` | 0 |
| 4 | **Образцы**: по 1 шт каждого цвета от 2–3 фабрик; **тест под главные жалобы покупателей** (темы ≥ 5 % из `product_deep`): для каждой — как проверяем и порог. Примеры: лента — груз ×2, 100 растяжений, −18 °C; сумка — запах 24 ч, ручки 8 кг ×20, молния 200 циклов, форма, размер ±1 см, цвет. Фото/видео тестов → в карточку | `reports/product_deep_<id>_*.md` → чек-лист в rfq-файле | цена образцов |
| 5 | **Документы**: «Честный знак» по коду ТН ВЭД, декларация/отказное письмо, маркировка EAC, кто оформляет ГТД | Exa (поиск в вебе, 2–3 источника; при расхождении — вопрос декларанту), `docs/wb_help/` | 0 |
| 6 | **Размер партии**: деньги на товар + реклама 3 месяцев + резерв; дни без товара по `budget_sim` ≤ 30 за полгода | `python -m src.budget_sim` | 0 |
| 7 | **3 условия до оплаты** (из премортема): цена «под ключ» ≤ порога; тест образцов без брака; СПП на нашей карточке в нужной полосе | `reports/premortem_*.md` | 0 |

## Что получите
Таблица «под ключ» (было → стало), решение по партии (сколько штук, сколько денег на что), статус 3 условий ✅ / ⚠️,
готовый текст письма поставщику. Конец — «Следующий шаг».

## Что можно поменять
| Что | Где |
|---|---|
| Порог цены «под ключ», маржа | `config/unit_economics.yaml`, решение в `reports/decision_*.md` |
| Курс, НДС, пошлина, фикс таможни | `config/landed_cost.yaml` |
| Бюджет и доли | `config/scoring.yaml` |

## Правила
Письма поставщикам и любые платежи — **только после «да» пользователя**. Ключи и пароли в письма не вставлять.
