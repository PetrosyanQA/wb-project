# Анализ товара — главный порядок (версия 2026-11-02, после аудита)

Запрос пользователя: **$ARGUMENTS**. Если пусто — анализ текущего товара из `PROJECT_STATE.md`.

## Как читать этот файл
6 этапов. На каждом есть **ворота**: прошёл → следующий этап; не прошёл → **стоп** и честный ответ «почему нет» (подгонять нельзя).
У каждого шага указано: чем считать, сколько стоит, где правда. Цифра без источника → «—» и причина.
Ответ — по-русски, полностью в чат, копия — в `reports/analiz_<товар>_<дата>.md`.

## Режим запуска (выбрать сам по запросу) и минимальный путь
Режим проекта — **только** `config/decision_current.yaml`: `FROZEN_TEST` — новые идеи только в `docs/kopilka.md`;
`DISCOVERY` / `VALIDATION` — поиск разрешён. Обязательные шаги — ниже; остальные — если ворота требуют. Бюджет — потолок на прогон
(Saleflow / Bright Data); выше — сначала спросить пользователя.

| Запрос | Режим | Обязательные шаги | Бюджет SF / BD |
|---|---|---|---|
| «сделай анализ» / «проверь наш товар» | **Проверка текущего** | 0.0, 0.0b, 0.1, 2.1, 2.3, 2.3b, 2.4, 3.1, 3.4, 4.0, 5, 6 | ≤ 15 / ≤ 5 |
| «усиль / уникальность нашего товара» | **Усилить текущий** | 0.0, 0.0b, 1.0 (фишки и комплекты для нашей ниши), 1.2, 2.0, 2.2 (¥ новой детали), 2.3, 4.0, 5, 6 | ≤ 10 / ≤ 10 |
