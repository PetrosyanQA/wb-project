# Аудит скилла /analiz и план улучшений — 02.11.2026

## Context
Пользователь: «Скил анализ как работает — сделай аудит и дай рекомендации». Сегодня /analiz реально прогнали 3 раза
(радар трендов, уникальность кистей и других ниш, триммеры) — аудит основан на том, что сработало и что нет.
Файл: `.claude/commands/analiz.md` (135 строк, 6 этапов, ~40 шагов).

## Как работает сейчас (кратко)
Этап 0 подготовка (режим, инструменты, уроки, лимиты, ключ WB, свежесть СПП/комиссий) → 1 уникальность (Exa-радар → продажи
за рубежом → живая выдача WB) → 2 четыре проверки (спрос, ¥ 1688, экономика, документы) → 3 глубокая (сегменты, формат,
новички, жалобы, реклама, габариты, выкуп, модель на лидере, карточки) → 4 решение (`src/decision.py`, стоп-решение, план,
kill) → 5 самопроверка + обучение → 6 ответ по шаблону.

## Что работает хорошо
- Ворота «стоп, если» и урок «нужен спрос на WB» — сегодня отсекли 9 из 10 кандидатов честно.
- Exa-радар (1.0) — бесплатно дал реальные цифры TikTok/Amazon/Etsy; живая выдача (1.2) — быстро.
- Экономика только через `unit_econ` / `white_import` / `commission.py`, 3 сценария СПП, решение через `decision.py`.

## Рекомендации = план правок
### 1. Новый скрипт `src/radar.py` (P2, P4, P11) — переиспользует `src/saleflow_stdio.Client.call`
- `python -m src.radar check "<запрос>" ["<запрос2>" …] --name <тема>`: вызывает `wb_check_rates` (limit 100), сохраняет сырой
  JSON в `data/raw/saleflow/<дата>/radar/<тема>/<запрос>.json`, печатает **короткую сводку**: всего, реклама в топе,
  органика, «сильные аналоги» (> 200 отзывов, доставка ≤ 120 ч), кросс-бордер (доставка > 120 ч) отдельно, сумма и медиана
  `sales`, диапазон цен, subject (предмет) самых частых карточек.
- Вердикт по правилу: `UNIQUE` (сильных < 5 и есть продажи у локальных), `CROWDED`, `NO_DEMAND_SIGNAL` (продаж нет ни у кого).
- Тест в `tests/` на разбор сводки по сохранённому JSON (без сети).

### 2. Правки `.claude/commands/analiz.md`
- **Режимы** (P3, P5): добавить «**Усилить текущий**» = 0 → 1.0 (Exa: фишки/комплекты для нашей ниши) → 1.2 → 2.2 (¥ новой
  детали) → 2.3 → 6. Строку про стоп-решение заменить на «режим берётся из `config/decision_current.yaml`: FROZEN_TEST —
  только копилка; DISCOVERY — поиск разрешён».
- **Минимальный путь** (P6): для каждого режима — список обязательных шагов (≤ 12) и бюджет: Поиск ≤ 40 Saleflow / ≤ 20 BD,
  Проверка ≤ 15 / ≤ 5, Усилить ≤ 10 / ≤ 10.
- **1.2** → через `src/radar.py`; кросс-бордер не считать ни аналогом, ни доказательством отсутствия спроса (P2).
- **Новый 1.2b «Спрос без аналогов»** (P1): частота запроса — Saleflow (поисковые запросы предмета, поле `wb_count` =
  частота, см. память saleflow-keywords-fields) или SellerMoon в браузере; ворота: ≥ 3 000 запросов/мес по главной формулировке
  или продажи у похожих локальных карточек.
- **Новый 1.4 «Предмет»** (P9): subject из сводки radar → `wb_seller subjects` → ID для 2.1.
- **2.2/2.3** (P7): сначала потолок ¥ (`screen_white.econ` / `unit_econ`), потом цена 1688.
- **Новый 2.5 «Сроки и сезон»** (P8): срок образец+партия+доставка vs месяц пика; не успеваем — старт под следующий сезон.
- **1.0** (P10): цифры сторонних сервисов — метка «оценка», для решения ≥ 2 независимых источника.
- **Этап 5**: прогнозы записывать одной командой в конце (минимум: СПП, ¥, продажи новичка) — пункт шаблона (P6).
- **Этап 6** (P12): добавить «Инструменты и расход» и «Что не проверено»; таблицу уроков сократить до 10 главных + ссылка на
